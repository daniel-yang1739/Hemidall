## 🎯 一、 階層劃分核心原則 (Tier Hierarchy Core Principle)

你的直覺**100% 完全精確**！這正是消除所有混亂的終極設計：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 🥇 第一層 (Top Tier / Root Nodes)：具備實體網路通訊與 Token 雲端計費邊界的步驟   │
│   • 👤 [USER]   使用者主動發話 (User Prompt ➔ 發送聯網計費)                   │
│   • ☁️ [CLOUD]  雲端模型思考、工具決策與最終回答 (GPU Prefill / Decode 計費)    │
│   • ⚙️ [SYSTEM] 系統開局約束與歷史 Checkpoint                                │
├─────────────────────────────────────────────────────────────────────────────┤
│ 🥈 第二層 (Sub Tier / Child Nodes)：純本機離線執行、當下 0 元的 Local Run       │
│   • 💻 [LOCAL]  實體終端命令 (RUN_COMMAND)、檔案讀取 (VIEW_FILE)、代碼變更等 │
│   • 永遠作為上方 [TOOL_CALL] 的子節點縮排呈現                                │
│   • 在此層標註「暫存中 ➔ 將在下一步打包計費」                                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 💡 三、 這種雙層結構帶來的 3 大核心優勢

1. **視覺心智模型 100% 統一**：
   * 眼睛掃描「第一層（凸出版面）」，看到的**全部都是真正發生網路通訊與雲端花費（GPU Token）的關鍵決策點**；
   * 看到「第二層（縮排節點）」，大腦立刻知道這是**本地作業系統代跑的工具成果**。
2. **因果關係不證自明**：
   * 子節點直接連在發起它的 `TOOL_CALL` 之下，不用任何人解釋誰是誰叫的；
3. **`p` / `n` 快捷鍵完全直覺化**：
   * 在第二層子節點按 `p` $\implies$ 往上一層跳回父層 `TOOL_CALL`；
   * 在第一層父節點按 `n` $\implies$ 往下一層展開選取子層 `RUN_COMMAND`！
